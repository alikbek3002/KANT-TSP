# bekemblock.kg — новый сайт

React + TypeScript на фронте, Node + Express на бэке. Главная построена вокруг
3D-модели газобетонного блока, которая поворачивается по мере прокрутки.

Палитра снята с логотипа: белый `#FBFBFB`, серый `#97989C`, голубой `#009EDD`,
красный `#EE353B`. Сайт светлый, токены — в `client/src/styles/tokens.css`.
Голубой логотипа на бумаге не читается текстом, поэтому у него два токена:
`--accent-bright` для света и графики, `--accent` (затемнённый) для надписей
и ссылок.

## Запуск

```bash
cd client && npm install
cd ../server && npm install && cp .env.example .env
cd .. && npm run dev          # клиент :5173, API :4000
```

Продакшен:

```bash
npm run build                 # сборка клиента и сервера
npm start                     # сервер отдаёт API и client/dist на :4000
```

## Модель

Исходник от дизайнера — `bekemblock_600x300x200.glb`, 14,8 МБ: 180 вершин и две
PNG-текстуры по 5–9 МБ внутри файла. Для веба текстуры вынуты и пережаты в WebP
1024×1024, GLB пересобран без них. Итог — 7 КБ геометрии плюс 200 КБ текстур.

Материал собирается в коде (`blockScene.ts`), потому что в исходнике неровности
заданы расширением `EXT_materials_bump`, которое three.js не читает: карта
навешивается вручную как `bumpMap`. Тайлинг текстуры 6⅔ — из `KHR_texture_transform`
исходной модели.

Если дизайнер пришлёт новую версию модели, пережать её заново:
вынуть картинки из GLB, сжать в WebP, собрать GLB без встроенных изображений.

## Шрифты

Заголовки — Unbounded (широкий геометрический гротеск с кириллицей), текст —
Onest, цифры и подписи выносок — JetBrains Mono. Все три с Google Fonts,
подключены в `client/index.html`.

## Хореография глав

Текста в потоке на главной почти нет: подписи живут на выносках, которые растут
из точек самого блока (`client/src/components/Callouts.tsx`). Линия идёт от
точки на блоке к подписи и заходит под её заголовок как подчёркивание — как
на чертеже. Размерные линии в главе про размеры считаются из спроецированных
рёбер, поэтому 600 / 300 / толщина всегда лежат по настоящим граням.

У каждой главы своя поза камеры (`POSES` в `three/blockScene.ts`): поворот,
наклон, расстояние и сдвиг. Между главами позы интерполируются, вес главы
(1 в центре, 0 у соседних) включает её эффекты и её выноски.

| Глава | Поза и эффект |
|---|---|
| 01 Блок | выезжает снизу при загрузке, тень проявляется под ним; паспорт блока на выносках |
| 02 Свойства материала | камера наезжает на угол и верхнюю грань, рёбра подсвечены |
| 03 Путь производства | длинная грань к зрителю, цвет уходит в сырой массив и возвращается, стадии стоят вдоль длины |
| 04 Линейка и размеры | блок перещёлкивается по пяти реальным толщинам 100…300, размерные линии по рёбрам |
| 05 Завод и цифры | блок встаёт в свой слот в кладке 2×2×3 на деревянном поддоне, кладка повёрнута вместе с ним |
| 06 Связаться | блок уходит вверх, под ним форма |

Толщина меняется масштабом по z, но текстура при этом не растягивается:
`ThicknessUV` в `three/blockAssets.ts` находит на каждой грани координату
текстуры, идущую вдоль z, и масштабирует её так же.

## Каталог

Четыре плотности: D400, D500, D600, D700 (на старом сайте были D400–D600,
на живом сейчас D500–D700 — взяты все четыре; характеристики типовые по
ГОСТ 31360-2007, заказчик подтверждает по своим протоколам).

`/catalog` устроен как главная: сцена закреплена, четыре блока стоят в ряд
(`three/catalogScene.ts`), камера едет вдоль ряда по мере прокрутки, активный
блок приподнимается и поворачивается в три четверти, соседи уходят в серый.
У каждого блока свои выноски: плотность и назначение, класс прочности, λ,
пора и морозостойкость, размерные линии 600 / высота / толщина. Чипы
типоразмеров внизу главы меняют размер всех блоков сразу. Сцена использует
тот же контракт `SceneOptions`/`SceneHandle`, что и главная, поэтому
`ScrollStage`, выноски и рейка глав общие — в него передаётся только фабрика
сцены (`createScene`).

## Движение блока по главной

Помимо поз у глав задан маршрут: в герое блок по центру, на «структуре»
уходит вправо и камера наезжает, на «производстве» — влево длинной гранью,
на «размерах» снова вправо торцом, на «заводе» встаёт в кладку, на «контакте»
поднимается над формой. Между главами он идёт дугой (подпрыгивает и чуть
приближается) с креном в сторону движения; скорость прокрутки добавляет
инерционный крен. Заголовки глав стоят с противоположной от блока стороны.

## Заявки

`POST /api/leads` — имя, телефон, типоразмер, комментарий, источник.
Один номер принимается не чаще раза в минуту. Заявки пишутся в
`server/data/leads.jsonl`; если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`,
дублируются в Telegram.

## Vercel

Живёт на https://bekemblock-site.vercel.app. Деплой из папки `bekemblock-site`:
`vercel deploy --prod --yes`. Конфиг — `vercel.json`: собирается `client`,
раздаётся `client/dist`, модель, картинки и ассеты кэшируются как immutable,
все остальные пути уходят в `index.html` (SPA).

API на Vercel — функции в `api/`: `api/leads.ts` (та же проверка, что на
Express-сервере; диска нет, поэтому заявка идёт в Telegram по переменным
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` и в лог функции) и `api/catalog.ts`
(копия каталога — правишь `server/src/catalog.ts`, правь и его).
Переменные для Telegram задаются в настройках проекта на Vercel.

Express-сервер в `server/` остаётся для обычного хостинга с диском.
